## Key Facts / Gotchas
- `YouTubeMusicSource` dispatches by **id shape**: `MPREb_…` album / `UC…` channel → InnerTube; URLs / bare names → NewPipe. Metadata falls back to NewPipe silently; stream resolution falls back only to a signed-in session on a bot wall (below).
- Search runs YouTube Music filtered searches at once: songs (released catalog only), albums, artists, and videos (`YtSearchFilter.VIDEOS`: music videos + fan uploads such as unreleased tracks, leaks, covers) only when `search(query, includeVideos = true)`. Only the Search screen asks, following pref `search_videos` (Settings → Search → Videos in search, default off); Wear / Auto / voice / song actions don't. Fan uploads credit a `MUSIC_PAGE_TYPE_USER_CHANNEL` channel, kept as name-only artist refs. The Search screen shows All (5 songs + 5 videos previews) / Songs / Videos chips.
- Artist page songs = the "Top songs" list shelf + its "Show all" list (`VLOLAK5…`, 2nd request, first 100), then de-duplicated by title and capped at 50. The page's "Videos" / "Live performances" carousels are music videos of the same songs under other ids, so they're left out (they caused repeated songs).
- Playlist import (`PlaylistImportRepositoryImpl`): `parseImportLink` decides the service. YouTube / YouTube Music lists are read whole via `MusicRepository.fullPlaylist` (InnerTube continuations, 100 per page, up to 5,000; NewPipe paging as fallback) and saved song for song. Spotify (embed `__NEXT_DATA__`) and Apple Music (page's `serialized-server-data` JSON, ≤300 songs = Apple's share limit) are matched with `searchSongs` (songs-only search), 4 at a time, taking the first of the top 5 results within ±10 s of the original length.
- Song cache (`MediaCacheModule` `SimpleCache` in `cacheDir/media`): Settings → Downloads has "Cache played songs" (pref `cache_songs`, default on; PlaybackService picks cache vs plain data source per load), "Cache size limit" slider (pref `cache_limit_mb`, 256 MB–16 GB, default 512) and "Clear cached songs". `data/cache/AdjustableLruCacheEvictor` reads the limit on every check; lowering it trims immediately via `CachedSongsRepository.trimToLimit()` under the cache's monitor.
- Stream URLs expire (~6h) and are IP-bound → resolved per track at load via `StreamUrlResolver`, never cached long.
- Lyrics sources run in the user's Settings order: Apple Music, BiniLyrics, LyricsPlus, SimpMusic, LRCLIB, KuGou, Unison, YouTube Music by default. Disabled sources are never contacted. When BiniLyrics is enabled, it identifies the exact recording ISRC first (2.5 s cap, small in-memory per-song LRU) while non-ISRC sources start immediately; BiniLyrics/LyricsPlus then use that ISRC when available. **Prefer word-by-word lyrics** is on by default: the repository ranks verified word-timed lyrics highest and gives slower synced sources a 2.5 s grace window before falling back to line-timed/plain results. With the preference off, the legacy source-order selection remains: first verified synced, else first synced, else first plain.
- Lyrics auto-sync: lyrics are timed to the release's audio, but a music video (`MUSIC_VIDEO_TYPE_OMV`/`UGC`) usually has an intro, so "unverified" lyrics (length mismatch) run early. `MusicRepository.albumAudio(id)` → `AlbumAudio.Same` (player endpoint says `…_ATV`, or a restricted video already plays its audio version) / `Other(song)` (via `pickAudioVersion`) / `Unknown`. `LyricsSyncRepositoryImpl` decodes two 30 s windows of the playing track (past the first 30 s, near the listener, 45 s apart) and the album audio's matching span with `PcmSnippetDecoder` through a read-only cache source, then `AudioAlignment` correlates 10 ms log-energy onsets over offsets −20…+60 s. Applied only if both windows score ≥ 0.30 and agree within 60 ms (repetitive beats fool one window, not two); a single window needs 0.50 and a clear peak. Result → the per-song lyrics offset (<150 ms counts as in time). `PlayerViewModel.autoSyncLyrics()` runs once per track per session when the lyrics panel shows synced, unverified lyrics with no manual offset; "Sync now" in the sync sheet forces it. Checked live: Blinding Lights video +22.65 s, Shape of You +6.10 s, Despacito +21.16 s, Uptown Funk +0.04 s; Kesariya synthwave remix vs film song rejected. YouTube Music's own Song/Video `counterpart` segment map isn't returned to signed-out clients, hence the audio matching.
- Age-restricted videos can't be played without sign-in (NewPipe throws `AgeRestrictedContentException`; no anonymous client bypass left since 2024). `YouTubeMusicSource.resolveStream` then plays the same song's audio-only version found by YouTube Music song search (`pickAudioVersion`: same core title and version, same artist, or YouTube Music's top result), cached per id; `song()` falls back to InnerTube `/player` `videoDetails` for their metadata. With a signed-in account and no audio version, the video itself plays via `SignedInStreamResolver`.
- **YouTube bot wall / optional Google sign-in**: when NewPipe throws `SignInConfirmNotBotException` (or `ReCaptchaException` on 429), YouTube has blocked anonymous playback for the IP. NewPipe's streams come from YouTube's Android/iOS/visionOS clients, which ignore browser cookies, so `SignedInStreamResolver` asks InnerTube `signedInPlayer` (clients `YtPlayerClient.TV` = TVHTML5, then `WEB_REMIX`) with the session's cookies + `SAPISIDHASH` (`YtCookieAuth`), decodes ciphered/`n` URLs with NewPipe's `YoutubeJavaScriptPlayerManager` and picks a format with `pickSignedInFormat`. After a block, signed-in playback goes first for 30 min. Signed out → `YouTubeAccount.requestSignIn(BLOCKED)` + `SignInRequiredException` (domain); `PlaybackService` sees it in the cause chain and stops the retry/skip loop. Root shows `YouTubeSignInPromptDialog` → `GoogleSignInDialog` (full-screen WebView on accounts.google.com → music.youtube.com; captures youtube.com cookies when `SAPISID` appears), then `MediaControllerManager.retryAfterError()`. Settings → YouTube account signs in/out. All clients rejecting the session → `onSessionRejected()` forgets it and prompts `EXPIRED`. Cookies live in private prefs `youtube_account.xml`, excluded (with `app_webview/`) from backup and device transfer. Untested against a live signed-in account (this dev machine's IP was already bot-walled for anonymous web clients on 2026-10-04).
- NewPipeExtractor: v0.26.5 is the newest release as of 2026-10-04 (dev only has SoundCloud fixes, dependency bumps, removal of broken YouTube clients).
- **YouTube personalisation** (read-only): `YouTubePersonalization.cookie()` = account cookie only when signed in **and** pref `personalize_youtube` (Settings → YouTube account, default off, not in backups). InnerTube methods take an optional `cookie` (adds Cookie + SAPISIDHASH for origin music.youtube.com, omits anonymous visitorData and never stores a signed-in one). Used by `YouTubeMusicSource`: `homeFeed` (personal FEmusic_home → `HomeFeed.personalized`, placed first on Home and not trimmed; continuations retried anonymously), `relatedTo` (signed-in Related tab), `personalRadio` (`upNext`: watch playlist `RDAMVM<id>` queue → first hop of `MusicRepository.radio`), private playlists / Liked music `LM` (only after the anonymous request comes back empty), `accountLibrary` (FEmusic_liked_playlists grid + FEmusic_library_corpus_artists → Library "Your YouTube Music playlists/artists"), `accountHistory` (FEmusic_history → merged into `TasteProfile` recentlyPlayed in Home's network phase). Every call falls back to anonymous. Home rebuilds when personalisation turns on/off. Nothing is written to the account (no likes, no history pings).
- `AudioStreamSelection` prefers AAC (M4A) over Opus: a Samsung Android 17 Opus decoder build outputs digital silence. Only progressive streams are picked (the player builds a progressive source before resolving, so HLS/DASH would fail and skip). Made-for-kids videos (and SABR-limited responses) offer no audio-only stream, only muxed 360p MP4 itag 18 → `pickMuxedStream` plays its AAC track; PlaybackService disables video tracks.
- Crossfade/Mix runs inside the **main player's own stream** (no second player); `crossfadeMs = 0` and Mix off → native gapless. Ahead of the end, the next track's opening is decoded (`PcmSnippetDecoder`, stereo) and `DjFilterProcessor` fades the current track out and mixes that opening in, both by **media time** (sample-exact, whatever is buffered). ~4 s before the end the next item's default start position is moved (`MixStartSource`, on the playback thread) so the gapless auto-advance continues it exactly where the mix got to; the processor patches the last few ms at the join (pads from the mix or drops the repeat). Media3 hands processors after TrimmingAudioProcessor an offset reduced by encoder delay+padding, so DjRenderersFactory's ForwardingAudioSink reports the trim and DjFilterProcessor adds it back; joins only happen when the outgoing stream played to its end. A second ExoPlayer lined up by reported positions was tried and failed on device: positions jitter by ±270 ms. Nothing is time-stretched, so beats are only matched when tempos already agree. Never touch `player.volume` for fades. Artwork follows the blend: once armed, `CrossfadeController` publishes a `MixBlend` (outgoing id, next `Song`, media-time window) on the `@Singleton` `MixTransitionBus` (service and UI share the process); `PlayerViewModel.mixBlend` → `ui/components/MixArtwork` (`rememberMixArtState` / `MixArtOverlay` / `rememberMixedAccent`) fades the next cover in by playback position on Now Playing (cover square, blurred backdrop + its accent tint; the Top-style video fades out), the mini player thumbnail, and Ambient (sleeve, wash, glow/aurora accent). Eases back on cancel; on finish the overlay is held 1.2 s while the screens' own track-change animations catch up, and the bus keeps a finished blend 1.5 s so the session's track change lands first.
- Now Playing slider = system media volume via Media3 device volume (`setDeviceVolumeControlEnabled(true)` in PlaybackService; `MediaControllerManager.setSystemVolume`, `PlayerState.systemVolume`). `Player.volume` (`PlayerState.volume` / `setVolume`) is only the sleep-timer fade gain; the platform session stays local so hardware keys are unaffected. ExoPlayer only re-reads STREAM_MUSIC on VOLUME_CHANGED_ACTION, so PlaybackService writes the current level back on output changes (`AudioOutputManager.state.current`) to refresh it.
- `AudioOutputManager` routes via `setPreferredAudioDevice` (MediaRouter route selection doesn't move media audio since Android 10).
- Media3 unstable APIs opted in with `@UnstableApi` (PlaybackService, StreamUrlResolver, CrossfadeController).
- `MusicLibraryCallback.onConnectAsync` gives untrusted controllers `DEFAULT_PLAYER_COMMANDS`. Media3 1.11 would otherwise make them read-only, and watch bridges (Galaxy Watch plugin) connect untrusted.
- Lyrics keep the display on via `ui/components/KeepScreenOn` (view `keepScreenOn`, not the window flag Ambient mode owns) while the lyrics overlay is shown, playing, and the player is expanded (`LocalPlayerExpanded`; the sheet stays composed when collapsed).
- Nav destinations use `ui/components/ScreenBackHandler` (not raw `BackHandler`): it disables itself while `LocalPlayerExpanded` so back collapses the player sheet instead of popping the screen behind it.
- Compose eats Back as "focus Exit" while anything is focused → root clears focus when the player sheet opens; `SearchScreen` drops focus after submit/tap/ON_STOP.
- Bottom chrome = `navigation/FloatingBottomBar` (tab pill + search + mini player). Root watches scrolling via a `NestedScrollConnection` on the NavHost: scroll down → minimised; scroll up / route change → expanded. Bar always reports expanded height, so `LocalBottomBarPadding` stays stable. Gated by pref `minimize_bar_on_scroll` (default off on low-RAM devices), read at root via `AppIntentViewModel`.
- Landscape (width > height and ≥ 600dp, `useSideDock`) swaps the bottom bar for `navigation/SideDock`: a vertical glass dock on the start edge (search + tabs). The NavHost is padded by the measured dock width, and the mini player floats alone at the bottom, centred over the content.
- Now Playing motion art has 3 styles, `ui/player/MotionArtStyle` (CARD / EDGE "Top" / FULL_SCREEN), pref `animated_artwork_style` (falls back to legacy bool `animated_artwork_full_screen`). EDGE = video filling the top `EDGE_HEIGHT_FRACTION` (65%) edge to edge, bottom faded with a DstIn mask. Cosmetic videos play only while `LocalPlayerExpanded`.
- Ambient mode (`ui/player/AmbientScreen`) can show a cassette instead of the sleeve: toggle button in its controls, pref `ambient_cassette` (default on). `AmbientCassette` draws the shell/window/reels on Canvas with the cover art as label (accent-tinted shell, retro stripes, Side A badge, metal screws, glossy packs, breathing glare); in landscape the clock heads the text column so it never overlaps the centrepiece; reels spin only while playing (empty hub faster, constant tape speed), packs move left → right by song progress (area-scaled), and seeks/new tracks spin a quick rewind. Animation state is read only in draw, and the frame loop idles when paused.
- Overscroll is iOS-style bounce app-wide: `ui/theme/BounceOverscroll.kt` (`BounceOverscrollFactory`) is provided as `LocalOverscrollFactory` in `MusicSMTheme`, replacing Android's stretch for every Lazy list/grid/row, `verticalScroll` and pager. Rubber-band pull on drag, spring back on release, critically damped bounce with the fling's leftover velocity (capped at 12% of the container). Parents that consume leftover scroll first (pull-to-refresh) still win. Home opts out via `WithoutBounce` (in `MusicSmNavHost`), which re-provides the platform stretch captured as `LocalPlatformOverscrollFactory`.
- Home "daily" shelves use `DailyRotation` (stable within a day), not `shuffled()`.
- Playlist sharing is backend-free: the whole playlist is encoded in the link / QR payload.
- `:innertube` and `:motionart` are plain JVM on purpose → parsers testable without Android.
- Build: needs `JAVA_HOME` = Android Studio JBR; `android.disallowKotlinSourceSets=false` (AGP9 built-in Kotlin + KSP).
- Not Play-shippable (YouTube ToS + GPLv3 from NewPipeExtractor); distributed via GitHub releases (`AppUpdater`) and `web/`.
